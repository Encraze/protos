# Stage 1 (MVP) — Roadmap

**Date:** 2026-04-28
**Source specs:** `docs/tech-task.txt`, `docs/spec-addons.md`, `docs/design-system.md`

This is a one-page roadmap, not a plan. It lists the subsystems Stage 1 needs and their dependency order. Each subsystem will be built directly when its turn comes — no separate per-subsystem plan documents.

## Built (foundation, in repo)

- Repo layout: `api/`, `web/`, `infra/`, `docs/`.
- FastAPI api with structured logging, async SQLAlchemy, Alembic migrations.
- Stage 1 data model: tenancy + identity, security, quotas, usage, billing, conversations, governance, notifications, audit. See `api/app/*/models.py`.
- `/health` endpoint with happy + db-failure tests.
- Vue 3 + Vite + TypeScript + Tailwind console, status page hits api `/health`.
- docker-compose for local stack: postgres + redis + minio + api + web.
- Makefile bootstrap (`make dev`, `make test`, `make migrate`, etc.).

## Next subsystems (build order)

1. **Auth & multi-tenancy** — OAuth login (Google + GitHub), session security, tenant scoping middleware, audit-log writes. (Models exist; behaviour and routes do not.)
2. **Security core** — encrypted secret storage (envelope encryption), provider-key issuance, platform api-key issuance with scopes/expiry/revoke and one-time reveal.
3. **Unified LLM proxy** — `POST /v1/chat/completions` (sync + SSE), `POST /v1/estimate`, provider adapters for OpenAI/Anthropic/Gemini, tool-call pass-through, timeout/retry/error mapping.
4. **Rate limits & quotas** — sliding window over Redis, monthly hard caps, `X-RateLimit-*` headers, 429 with `Retry-After` (spec-addons §2.1).
5. **Usage logging & dashboard** — async write path, pricing catalog, cost computation, tenant + admin dashboards per `design-system.md` §5.1.
6. **Billing (Stripe)** — customer + subscription wiring, metered usage reporter, invoice display, overage notifier, webhook receiver.
7. **Governance v1** — optional prompt/response storage, conversation threads, PII detection (Presidio) detect/mask/pseudonymize, banned-terms / prompt-injection / unsafe-output rules with ignore/warn/block, per-chunk evaluation for streaming, Slack + email notifications.
8. **MVP polish** — admin UI, 5-step self-serve onboarding wizard (`design-system.md` §5.3), API docs (OpenAPI + curated quickstarts + pricing + security pages), MVP release-criteria smoke test.

Subsystems 5, 6, 7 can run partly in parallel after subsystem 4. Subsystem 8 closes Stage 1.

## Out of scope for Stage 1

- Spec-addons §2.2 (status page), §2.3 (sandbox keys — schema flag is in `api_keys.mode` for forward-compat, no UI/billing yet), §2.4 (request-tag dimensions — column reserved on `usage_events`), §2.5 (embeddings).
- All of spec-addons §3.x and "Deferred" section.
- `tech-task.txt` MVP cut list: ElevenLabs, LangSmith, Telegram, complex evals, SDKs, advanced prompt manager, data residency.
- Cloud provisioning (staging/prod). Local docker-compose only until target cloud and posture are decided.
